View Descriptor Protocol — Go demo

One Go process playing three roles that talk to each other over real HTTP: an API that attaches view descriptors to its data, a template server that serves templates by URL, and a BFF that resolves the template tree and renders the HTML you are looking at (§7.5).

Every page below carries a trace panel showing the descriptor it was rendered from. Nothing in this demo hardcodes a template choice — the server decides, the client obeys.

Failure modes

VDP composition is best-effort: prefer partial rendering over total failure (§9). These links break the dashboard on purpose.

  • ?fail=chart — a slot's template 404s. The slot is skipped, the template's own default content shows, and the rest of the page renders. (§9.1)
  • ?untrusted=1 — the referenced nav descriptor names a template outside the trusted allowlist. The client refuses to fetch it. (§10)
  • ?fail=integrity — the legend's published integrity digest cannot match its bytes. Treated as a fetch failure: the slot is skipped. (§3.6, §9.1)
  • ?fail=root — the root template 404s. There is no tree to compose, so the client falls back to the raw data. (§9.4)
  • ?fail=mapper — the descriptor names a mapper this client never registered. The root transform fails, and the client must not show the untransformed data — error only. (§9.4 rule 2, §9.6)

Look at the wire

The protocol is just HTTP. Watch it directly:

# The descriptor rides on a Link header; the body stays clean (§4.1)
curl -i localhost:8080/api/dashboard

# The descriptor resource it points to (§5)
curl -i localhost:8080/views/dashboard.json

# The nav descriptor it references from a slot (§3.7)
curl -i localhost:8080/views/nav.json

# The shorthand header, for the single-template case (§4.1)
curl -i localhost:8080/api/login

# Inline _views, offering two views of one payload (§4.2)
curl -s localhost:8080/api/products/42

# Discovery: trusted template URL prefixes and prefetchable descriptors (§13.2)
curl -s localhost:8080/.well-known/vdp

# VDP support advertised on OPTIONS (§13.1)
curl -i -X OPTIONS localhost:8080/api/dashboard

# A template resource, fetched by URL like any other (§5.2)
curl -s localhost:8080/templates/layouts/sidebar.html
